# 004. 단지 정보를 명부별로 나눠 받고, 짝을 못 찾은 단지는 비워 두기로 한 이유

- 상태: 확정
  - 시점 : 코드 작성 전/선택 전
  - 질문 : 왜 A가 아니라, B인가 판단
  - 핵심 : 트레이드오프

## 맥락

stance 는 실거래가 있는 단지마다 명부(단지 목록과 속성을 담은 공공 자료)에서 짝을 찾아 세대수, 사용승인일, 면적별 세대수, 관리정보를 붙인다. 실거래와 명부에는 공통 번호가 없어 도로명 주소로 짝을 찾는다.

처음 쓴 K-apt 명부로는 실거래 단지의 3분의 1 정도만 짝을 찾았다. 못 찾은 단지는 대부분 몇십 세대짜리 작은 단지였다. K-apt 는 관리 의무가 있는 큰 단지 위주라 작은 단지가 애초에 없다. 문제는 짝을 찾는 규칙이 아니라 명부의 범위였다.

## 검토한 선택지

### 1. 어느 명부를 쓸 것인가

| 선택지 | 판단 |
| --- | --- |
| K-apt 파일만 | 3분의 1 정도만 짝을 찾는다. 여러 차수를 한 단지로 묶어 둔 곳은 세대수가 몇 배로 붙는다 |
| K-apt 오픈API | 파일과 범위가 같다 |
| 한국부동산원 단지 식별정보 + 주택 공시가격 | 95% 정도가 짝을 찾는다. 차수도 따로 나뉘어 있고, 공시가격으로 면적별 세대수를 만들 수 있다 |
| 건축물대장 | 필지 단위라 단지로 묶는 규칙부터 새로 만들어야 한다 |

### 2. 주소로 짝을 못 찾으면 어떻게 할 것인가

| 선택지 | 판단 |
| --- | --- |
| 이름이 비슷하면 붙이기 | 같은 단지도 자료마다 이름이 다르고, 다른 단지가 같은 이름을 쓰기도 한다 |
| 지번, PNU(필지고유번호)로 다시 찾기 | 도로명이 안 될 때 쓰는 보조 방법 |
| 표기 차이 맞추기 | 띄어쓰기, 앞자리 0 같은 차이를 맞춰 다시 찾는다 |
| 후보 중 하나 고르기 | 같은 주소에 단지가 둘 이상인 경우가 200개 가까이 있다 |
| 이름이 똑같은 후보로 고르기 | 후보 중 이름이 글자까지 같은 단지가 하나면 그것을 고른다 |

## 결정

세대수와 면적은 한국부동산원과 공시가격에서, 관리정보는 K-apt 에서 가져온다. 짝을 찾는 규칙은 그대로 두고 찾아볼 명부만 바꾼다.

| 정보 | 출처 | 짝을 찾는 단지 |
| --- | --- | --- |
| 세대수, 사용승인일 | 한국부동산원 단지 식별정보 | 95% 정도 |
| 면적별 세대수 | 주택 공시가격 | 위에서 짝을 찾은 단지 |
| 관리정보 (복도, 난방, 주차) | K-apt | 3분의 1 정도 |

- 도로명 주소가 정확히 같고 후보가 하나일 때만 짝으로 본다.
- 표기 차이는 맞췄을 때 기존 짝을 잃지 않고 새 짝만 생길 때만 맞춘다.
- 면적은 0.5제곱미터 안에서 가장 가까운 하나에 붙이고, 가장 가까운 것이 둘이면 붙이지 않는다.

**이렇게 정한 이유**

1. **거래가 있는 단지에서 출발한다.** 거래가 없는 단지는 보여 줄 가격이 없다.
2. **이름이 아니라 주소로 찾는다.** 이름은 자료마다 다르게 적혀 있지만 도로명 주소는 한 건물을 가리킨다. 실제로 주소로 찾은 짝은 한 쌍을 빼고 준공 연도가 모두 같았다. 그 한 쌍은 같은 자리에 재건축한 단지다.
3. **모르면 비워 둔다.** 짐작으로 붙였다가 틀리면 사용자도 앱도 알 수 없다. 비워 두면 "정보 미확인"으로 드러난다. 여러 단지가 명부의 한 단지를 함께 가리킬 때도 세대수를 나누지 않고 비운다.

**앱에서 보이는 모습**

| 상태 | 앱 |
| --- | --- |
| 짝 찾음 | 세대수, 사용승인일, 평형을 보여 준다 |
| 거래는 있고 짝 없음 | 거래는 보여 주고 빈 칸은 "정보 미확인" |
| 거래 없음 | 앱에 나오지 않는다 |

**한계**

- 명부는 1년에 한 번 새로 나온다. 갓 입주한 단지는 다음 판까지 미확인이다. 새 단지를 대응표에 넣는 작업도 아직 사람이 돌린다.
- 관리정보는 여전히 관리 의무 단지에만 있다. 주차대수를 어디서 가져올지는 아직 정하지 않았다.
- 재건축 전후 단지가 같은 주소로 엮이면 준공 연도로만 알아챌 수 있다.

## 포기한 것 - 무엇을 만들지 않기로 했고 왜

- **이름이 비슷하면 붙이기.** 잘못 붙은 짝은 화면에서 맞는 짝과 구별되지 않는다.
- **지번, PNU 로 다시 찾기.** PNU 는 결국 지번이고, 지번은 K-apt 때 효과가 작아 이미 접었다. 기준이 둘이면 서로 어긋날 때 어느 쪽을 믿을지 또 정해야 한다.
- **이름이 똑같은 후보로 고르기.** 짐작은 아니지만 이름으로 찾는 방식은 이미 버렸다. 못 찾은 단지는 "미확인"으로 드러나고, 나중에 이 규칙을 더해도 기존 짝은 바뀌지 않는다.
- **K-apt 오픈API.** 파일과 범위가 같다.
- **공시가격 원본을 호 단위로 DB 에 넣기.** 서울만 수백만 호인데 쓰는 것은 단지별 면적과 호 수뿐이다. 원본은 로컬에서 집계하고 해시로 판을 고정해 다시 만들 수 있게 했다.
